# Health Checks

AxiSpark.js includes a health engine that reports the status of the application, each registered plugin and each health check. The plugin status is calculated from the plugin lifecycle, and health checks report the status of external dependencies such as databases, brokers or APIs.

## HealthEngine

`HealthEngine` is created by the application context and bound in the dependency injection container. You can inject it in any injectable class:

```ts title="status-service.ts"
import { HealthEngine, HealthStatus } from '@axisparkjs/core';
import { Injectable } from '@axisparkjs/di';

@Injectable()
export class StatusService {
    constructor(private readonly healthEngine: HealthEngine) {}

    public async isHealthy(): Promise<boolean> {
        const app = await this.healthEngine.checkApp();
        return app.status === HealthStatus.Healthy;
    }
}
```

It exposes these methods:

| Method | Returns |
| --- | --- |
| `checkAll()` | A promise with an array of `HealthData`. The first item is the application status, followed by one item per registered plugin and one item per health check. |
| `checkApp()` | A promise with only the application `HealthData`, the first item of `checkAll()`. |
| `register(indicator, options?)` | Registers a `HealthIndicator` instance. Plugins use it to register the checks of their connections. |

## Custom Health Checks

Create a class that extends `HealthIndicator` and decorate it with `@HealthCheck`. The class is discovered automatically by the scanner, resolved through the dependency injection container and run every time the health of the application is checked, so it can inject other services:

```ts title="payments-api-health.ts"
import { HealthCheck, HealthCheckResult, HealthIndicator, HealthStatus } from '@axisparkjs/core';
import { PaymentsClient } from './payments-client';

@HealthCheck({ name: 'payments-api', timeout: 2000 })
export class PaymentsApiHealth extends HealthIndicator {
    constructor(private readonly client: PaymentsClient) {
        super();
    }

    async check(): Promise<HealthCheckResult> {
        const latency = await this.client.ping();
        return { status: HealthStatus.Healthy, details: { latency } };
    }
}
```

`check()` returns a `HealthCheckResult` with a `status` and optional `details`, which are included in the health response. If `check()` throws an error or exceeds its timeout, the check is reported as `Unhealthy` and the error message is added to `details.error`.

`@HealthCheck` accepts these options:

| Option | Default | Description |
| --- | --- | --- |
| `name` | Class name | Component name of the check in the health response. |
| `timeout` | `5000` | Maximum time in milliseconds for the check. If it is exceeded, the check is reported as `Unhealthy`. |
| `critical` | `true` | Whether a failure of the check makes the whole application `Unhealthy`. Non-critical checks are reported, but they do not change the application status. |

All checks run in parallel, so a slow check does not delay the others and the health endpoints never wait longer than the highest timeout.

## Built-in Checks

The connection plugins register one health check per configured connection:

| Plugin | Component name | Check |
| --- | --- | --- |
| [Data Plugin](../data-plugin/installation) | `data:<name>` | Runs `SELECT 1` on SQL data sources (`SELECT 1 FROM DUAL` on Oracle) and `ping` on MongoDB. |
| [Kafka](../connections/kafka) | `kafka:<name>` | Connects an admin client, without retries, and describes the cluster. |
| [RabbitMQ](../connections/rabbitmq) | `rabbitmq:<name>` | Checks that the connection is open and reports its number of channels. |

If a connection drops after the application has started, its check reports `Unhealthy`, and so does the application. The built-in checks are critical and use the default timeout. Disable them with the `healthChecks: false` plugin option:

```ts title="app.ts"
app.use(
    KafkaPlugin,
    KafkaPluginOptionsFactory.create({
        connections: [{ name: 'ORDERS', config: { brokers: ['localhost:9092'] } }],
        healthChecks: false
    })
);
```

## HealthData

Each item is returned as a `HealthData` object:

```ts
interface HealthData {
    /** Application name, plugin class name or health check name. */
    component: string;
    /** HealthStatus.Unknown ('unknown'), HealthStatus.Healthy ('healthy') or HealthStatus.Unhealthy ('unhealthy'). */
    status: HealthStatus;
    /** ISO 8601 date when the check was calculated. */
    timestamp: string;
    /** Additional information about the component. */
    details?: Record<string, any>;
}
```

- For a plugin, `details` contains the plugin name (`plugin`) and, when the plugin failed, the error message (`error`).
- For a health check, `details` contains the `details` returned by the check, whether the check is `critical` and, when the check failed, the error message (`error`).
- For the application, `details.plugins` contains the `component` and `status` of every plugin, and `details.checks` the `component`, `status` and `critical` flag of every health check.

## Plugin Status

The status of each plugin is mapped from its lifecycle state:

| Plugin lifecycle | `HealthStatus` |
| --- | --- |
| `Started` | `Healthy` |
| `Error` | `Unhealthy` |
| `Created`, `Registered`, `Stopped` | `Unknown` |

A plugin enters the `Error` state when one of its lifecycle methods (`onRegister`, `onStart` or `onStop`) throws an error.

## Application Status

The application status is calculated from the plugin statuses and the critical health checks:

- `Healthy` when every plugin and every critical check is `Healthy`.
- `Unhealthy` when at least one plugin or critical check is `Unhealthy`.
- `Unknown` otherwise, for example while the plugins are still registering or after they are stopped.

## HTTP Endpoints

The [Http Plugin](../http-plugin/installation) can expose the health engine through HTTP. Enable the `healthChecks` option:

```ts title="app.ts"
import { HttpPlugin } from '@axisparkjs/http';
import { HttpPluginOptionsFactory } from '@axisparkjs/http-express';

app.use(
    HttpPlugin,
    HttpPluginOptionsFactory.create({
        basePath: '/api',
        healthChecks: true
    })
);
```

The following endpoints are registered under the plugin `basePath`:

| Endpoint | Status code | Response |
| --- | --- | --- |
| `GET /health` | `200` when the application is healthy, `503` otherwise. | Application status and every item returned by `checkAll()`. |
| `GET /health/liveness` | Always `200`. | Application status. |
| `GET /health/readiness` | `200` when the application is healthy, `503` otherwise. | `healthy` status, or an error listing the components that are not healthy, excluding non-critical checks. |

### Example Responses

`GET /api/health` when the application is healthy:

```json
{
    "status": "healthy",
    "timestamp": "2026-01-01T10:00:00.000Z",
    "checks": [
        {
            "component": "My App",
            "timestamp": "2026-01-01T10:00:00.000Z",
            "status": "healthy",
            "details": {
                "plugins": [{ "component": "HttpPlugin", "status": "healthy" }],
                "checks": [{ "component": "payments-api", "status": "healthy", "critical": true }]
            }
        },
        {
            "component": "HttpPlugin",
            "timestamp": "2026-01-01T10:00:00.000Z",
            "status": "healthy",
            "details": { "plugin": "HttpPlugin" }
        },
        {
            "component": "payments-api",
            "timestamp": "2026-01-01T10:00:00.000Z",
            "status": "healthy",
            "details": { "latency": 12, "critical": true }
        }
    ]
}
```

`GET /api/health/liveness`:

```json
{
    "status": "healthy",
    "timestamp": "2026-01-01T10:00:00.000Z"
}
```

`GET /api/health/readiness` when a plugin and a health check failed:

```json
{
    "error": "Some components are not healthy: My App, BadPlugin, payments-api",
    "status": 503
}
```

> Use `/health/liveness` to check that the process is running and `/health/readiness` to decide whether the application can receive traffic.
