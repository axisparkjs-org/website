# Pipes

Pipes are a powerful feature of the engine system that allow you to transform and manipulate data when it is being injected into your engine steps. Pipes can be used to perform various operations on the data, such as validation, transformation, or formatting, before it is passed to the step.

A `Pipe` is a decorator that can be applied to a class, method, or property to specify a the transformations that will be applied to the data being injected. Pipes can be used in conjunction with parameters to create more complex and dynamic workflows. A pipe can include more than one transformation, and the transformations will be applied in the order they are defined. We will refer to these transformations as `pipe-steps`.

## Optional Parameters

The parsing pipe-steps fail when the parameter is missing: `@Query('page') @Pipe(ParseInt()) page: number` answers `400` for a request without `page`. Put `Default()` or `Optional()` before them to accept missing parameters:

```ts
import { Default, Optional, ParseDate, ParseEnum, ParseInt, ParseUuid, Pipe } from '@axisparkjs/engine';
import { Controller, Get, Path, Query } from '@axisparkjs/http';

enum OrderStatus {
    Open = 'open',
    Shipped = 'shipped'
}

@Controller('orders')
export class OrderController {
    @Get()
    list(
        @Query('page') @Pipe(Default(1), ParseInt()) page: number,
        @Query('status') @Pipe(Default(OrderStatus.Open), ParseEnum(OrderStatus)) status: OrderStatus,
        @Query('from') @Pipe(Optional(), ParseDate()) from: Date | undefined
    ) {}

    @Get(':id')
    find(@Path('id') @Pipe(ParseUuid()) id: string) {}
}
```

- `Default(1)` gives the value `1` to a missing `page`, and `ParseInt()` receives it.
- `Optional()` stops the pipe of a missing `from`: `ParseDate()` does not run and the handler receives `undefined`.
- Query parameters with an empty value (`?page=`) arrive as `''`. Use `{ emptyString: true }` to treat them as missing.

## Lists

`?tags=a,b` arrives as the string `"a,b"`, and `?tags=a` as a string, although the parameter is typed as `string[]`. Only `?tags=a&tags=b` is an array. `ParseArray()` returns an array in every case, and the `items` option converts each item with another pipe-step:

```ts
@Get()
list(
    @Query('tags') @Pipe(Default([]), ParseArray({ maxItems: 5, unique: true })) tags: string[],
    @Query('ids') @Pipe(Default([]), ParseArray({ items: ParseInt() })) ids: number[]
) {}
```

`GET /orders?tags=a,b&tags=c&ids=1,2` gives `tags = ['a', 'b', 'c']` and `ids = [1, 2]`. The items are trimmed and the empty ones removed. `minItems`, `maxItems` and `unique` (compared after the `items` pipe-step) throw a `PipeStepValidationError`.

## Schema Validation

`ValidateSchema()` validates structured data, such as a request body, against a DTO class decorated with [`class-validator`](https://github.com/typestack/class-validator) decorators. The class is not passed to the pipe-step: it is inferred from the type declared for the parameter, using the metadata TypeScript emits when `emitDecoratorMetadata` is enabled.

```ts
import { IsEmail, IsInt, Min } from 'class-validator';
import { Pipe, ValidateSchema } from '@axisparkjs/engine';

class CreateUserDto {
    @IsEmail()
    email!: string;

    @IsInt()
    @Min(18)
    age!: number;
}

@Controller('/users')
export class UserController {
    @Post()
    create(@Body() @Pipe(ValidateSchema({ whitelist: true })) user: CreateUserDto) {
        // `user` is a validated `CreateUserDto` instance
    }
}
```

When validation succeeds, the value is passed to the next pipe-step as an instance of the declared class. When it fails, a `PipeStepValidationError` is thrown, and its message lists every failing constraint with its property path (for example `email: email must be an email; age: age must not be less than 18`). Over HTTP, this error is returned as a `400 Bad Request` response.

`ValidateSchema()` accepts the following `class-validator` options, which are passed through unchanged:

```ts
export interface ValidatorOptions {
    skipMissingProperties?: boolean;
    whitelist?: boolean;
    forbidNonWhitelisted?: boolean;
    groups?: string[];
    dismissDefaultMessages?: boolean;
    validationError?: {
        target?: boolean;
        value?: boolean;
    };
    forbidUnknownValues?: boolean;
    stopAtFirstError?: boolean;
}
```

:::warning Runtime type limitations
TypeScript does not preserve interfaces, generic types, union types or type literals at runtime, so they cannot be used as inferred schemas. Primitive types (`string`, `number`, ...), `Object`, `Array` and `Date` are not supported either. Using `ValidateSchema()` on such a parameter throws a `PipeStepError` explaining that schema validation requires a class-typed parameter.

The incoming value is converted to an instance of the declared class without running its constructor, and nested objects are not converted. To validate nested objects with `@ValidateNested()`, they must already be instances of their own classes.
:::

## Creating Custom Pipe-Steps

You can create your own custom pipe-steps by implementing the `PipeStep` interface and defining the function that will be included in the Pipe decorator. A custom pipe-step can be used to perform any transformation or validation that is not covered by the built-in pipe-steps. Here is an example of how to create a custom pipe-step.

```ts
import { ParameterDefinition, PipeStep } from '@axisparkjs/engine';
import { Injectable } from '@axisparkjs/di';

// Transformation logic
@Injectable()
export class CustomCasePipeStep implements PipeStep<string, string> {
    execute(parameter: ParameterDefinition): any {
        ...
    }
}

// Function to include in the Pipe decorator
export const Custom = () => CustomCasePipeStep;
```

Pipe-steps can also include additional parameters to customize their behavior. For example, you can create a pipe-step that accepts a parameter to specify the number of decimal places to round a number to.

```ts
import { ParameterDefinition, PipeStep } from '@axisparkjs/engine';
import { Injectable } from '@axisparkjs/di';

// Pipe-step configuration interface
export interface CustomPipeStepConfig extends PipeStepConfig {
    value: number;
}

// Transformation logic
@Injectable()
export class CustomPipeStep implements PipeStep<number, number> {
    execute(parameter: ParameterDefinition, config: CustomPipeStepConfig): any {
        ...
    }
}

// Function to include in the Pipe decorator
export const Custom = (value: number) => {
    return {
        pipeStep: CustomPipeStep,
        PipeStepConfig: { value } as CustomPipeStepConfig
    };
};
```

A pipe-step can stop the pipe of its parameter by returning `PipeStepSkip`, as `Optional()` does: the rest of the pipe-steps are skipped and the handler receives `undefined`. The `execute` method also receives the `ExecutionContext` as an optional third argument.

```ts
import { ParameterDefinition, PipeStep, PipeStepSkip } from '@axisparkjs/engine';

@Injectable()
export class SkipNullPipeStep implements PipeStep {
    execute(parameter: ParameterDefinition): any {
        return parameter.value === null ? PipeStepSkip : parameter.value;
    }
}
```

##  Using Pipes in Engine Steps

In any engine step, you can use the `@Pipe()` decorator to specify the pipe-steps that will be applied to the data being injected. The `@Pipe()` decorator accepts one or more pipe-step functions as arguments. Here is an example of how to use pipes in an engine step.

```ts
import { EngineStep, Pipe } from '@axisparkjs/engine';

@Pipe(NotEmpty(), Trim())
export class Example {
    @Pipe(MaxLength(10))
    async execute(@AnyParamterDecorator() @Pipe(LowerCase()) input: string): Promise<void> {
        ...
    }
}
```

In this example, for parameter `input`, the 4 pipe-steps `NotEmpty()`, `Trim()`, `MaxLength(10)`, `LowerCase()` and  will be applied in the order they are defined. The data will first be checked to ensure it is not empty, then any leading or trailing whitespace will be removed, then it will be checked to ensure it does not exceed a maximum length of 10 characters, and finally it will be converted to lowercase before being passed to the `execute` method.

## Pipe-Step Errors

Pipe-steps report invalid input by throwing a `PipeStepParsingError` (the value cannot be converted, e.g. `ParseInt()`) or a `PipeStepValidationError` (the value does not meet a constraint, e.g. `Range()` or `ValidateSchema()`). Both extend `PipeStepError`.

Over HTTP, the global error filter returns parsing and validation errors as `400 Bad Request`, with the error class name as the `cause`:

```json
{
    "error": "Parsing failed for 'path' as integer: Value 'abc' is not a valid integer.",
    "status": 400,
    "cause": "PipeStepParsingError"
}
```

Any other `PipeStepError` signals a misconfiguration rather than invalid input (for example, `ValidateSchema()` on a parameter that is not typed with a class), so it is returned as `500 Internal Server Error`.

> `NotEmpty()` and `Trim()` are applied to the class, so they will be applied to all parameters of any method of the class. `MaxLength(10)` is applied to the method, so it will be applied to all parameters of the method. `LowerCase()` is applied to the parameter, so it will only be applied to that specific parameter.
