# Plugins

Plugins are a powerful feature of AxiSpark.js that allow you to extend the functionality of your application. They can be used to add new features, integrate with third-party services, or modify the behavior of existing components.

## Creating a Plugin

In AxiSpark.js, a plugin is a class that implements the `Plugin` interface. This interface defines the methods that a plugin must implement to be compatible with the AxiSpark.js application. Also, a plugin needs to be decorated with the `@Injectable()` decorator to be recognized by the dependency injection system.

```ts title="plugin.ts"
import { Plugin } from '@axisparkjs/core';
import { Injectable } from '@axisparkjs/di';
import { Logger } from '@axisparkjs/logger';

@Injectable()
export class ExamplePlugin extends Plugin {
    private context: AxiSparkContext;
    protected options: HttpPluginOptions;

    constructor(
        private readonly logger: Logger,
        private readonly injector: Injector
    ) {
        super();
    }

    async onRegister() {
        if (!options) throw new PluginNotConfiguredError(ExamplePlugin.name);
        this.context = context;
        this.options = options;
        this.logger = this.logger.child('ExamplePlugin');

        await this.logger.info('onRegister called');
    }

    async onStart() {
        await this.logger.info('onStart called');
    }

    async onStop() {
        await this.logger.info('onStop called');
    }
}
```

> The `onRegister`, `onStart`, and `onStop` methods are lifecycle hooks that allow you to perform actions at different stages of the plugin's lifecycle. You can use these methods to initialize resources, start background tasks, or clean up resources when the plugin is stopped.

## Lifecycle Order

The plugins are grouped by level of their dependency graph (`static dependencies`): the first level has the plugins without dependencies, and each next level has the plugins whose dependencies are in the previous levels. The plugins of a level run `onRegister` and `onStart` **at the same time**, after the previous level has ended, so independent plugins, such as the connections to Redis, Kafka and RabbitMQ, do not wait for each other at startup. `onStop` runs level by level in reverse order, so a plugin is stopped before the plugins it depends on.

Declare in `dependencies` every plugin that a plugin needs to be registered or started before it. When some plugins depend on each other without declaring it, run the lifecycle methods one by one, in dependency order, with the `pluginLifecycle` option of the application:

```ts title="app.ts"
AxiSparkFactory.create({ pluginLifecycle: 'sequential' });
```

## Adding a Plugin to Your Application

You can add a plugin to your AxiSpark.js application by using the `app.use()` method. This method takes a plugin class as a parameter and registers it with the application.

```ts title="app.ts"
app.use(ExamplePlugin);
```

If the plugin requires configuration options, you can pass them as a second parameter to the `app.use()` method:

```ts title="app.ts"
app.use(ExamplePlugin, { option1: 'value1', option2: 'value2' });
```

## Implemented Plugins

The are some plugins already implemented in AxiSpark.js, which you can use in your application. These plugins provide common functionality that can be useful in many applications.
