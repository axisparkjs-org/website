# Instrumentation hooks

The framework packages never depend on OpenTelemetry. They expose small hooks, which the `TelemetryPlugin` implements, so other implementations, such as a lightweight Prometheus-only one, can use them too. Without a registered hook, the cost is one `undefined` check.

| Package | Hook | Register it with |
| --- | --- | --- |
| `@axisparkjs/engine` | `ExecutionInstrumentation` | `ExecutionEngine.registerInstrumentation()` |
| `@axisparkjs/engine` | `RateLimitInstrumentation` | `RateLimitProcessor.registerInstrumentation()` |
| `@axisparkjs/schedule` | `JobInstrumentation` | `SchedulerRunner.registerInstrumentation()` |
| `@axisparkjs/store` | `StoreInstrumentation` | `registerStoreInstrumentation()` |
| `@axisparkjs/logger` | `LogEnricher` | `Logger.registerEnricher()` |

Each one accepts a single implementation, and passing `undefined` removes it. The `TelemetryPlugin` registers them when it is registered and removes them when it stops.

## Executions

`ExecutionEngine.execute()` is called by every transport (`HttpEngine`, `WebSocketEngine` and `McpEngine`), so one hook observes every handler:

```ts
interface ExecutionInstrumentation {
    /** Called before the plan runs. */
    start(context: ExecutionContext): ExecutionObserver | ((outcome: ExecutionOutcome) => void);
}

interface ExecutionObserver {
    /** Runs the rest of the execution, for example inside the context of a span. */
    run?<T>(execution: () => Promise<T>): Promise<T>;
    /** Called once when the execution ends, after the result has been processed. */
    end(outcome: { error?: Error }): void;
}
```

`outcome.error` is the error thrown by a step or the handler, also when a filter handled it. For HTTP, read the status with `context.response.statusCode`, and the route template with `context.route`.

A minimal implementation that logs the slow requests:

```ts
ExecutionEngine.registerInstrumentation({
    start(context) {
        const start = performance.now();
        return () => {
            const duration = performance.now() - start;
            if (duration > 1_000) console.warn(`${context.target.name}.${String(context.propertyKey)} took ${duration} ms`);
        };
    }
});
```

## Scheduled jobs

```ts
interface JobInstrumentation {
    start(job: JobDefinition, scheduledAt: Date): JobObserver | ((outcome: JobOutcome, error?: Error) => void);
}

type JobOutcome = 'executed' | 'skipped' | 'failed';
```

`start` is called before the lock of an exclusive job is acquired, so the skipped executions are observed too.

## Rate limits

```ts
interface RateLimitInstrumentation {
    decided(context: ExecutionContext, definition: RateLimitDefinition, decision: RateLimitDecision): void;
}
```

It is called after every request counted by `RateLimitProcessor`, for every transport.

## Stores

```ts
interface StoreInstrumentation {
    start(operation: { kind: StoreKind; operation: string }): (error?: unknown) => void;
}
```

The stores registered by the framework are wrapped with `instrumentStore(kind, store)`, so the instrumentation observes every call of their methods, whether it is registered before or after them. Wrap the stores of your own plugins with it to measure them too.

## Logs

```ts
type LogEnricher = () => LogMetadata | undefined;
```

The enricher is called for every entry of every logger. Its metadata is added before the metadata of the logger and of the entry, which override it. See [Logging](../getting-started/logging#trace-context).
