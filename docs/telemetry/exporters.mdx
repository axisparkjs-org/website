# Exporters

The plugin does not configure the exporters: the SDK of the application does. These are the most common setups.

## Prometheus

The Prometheus exporter serves the metrics on its own port, `9464` by default, at `/metrics`:

```bash
npm install @opentelemetry/sdk-node @opentelemetry/exporter-prometheus
```

```ts title="instrumentation.bootstrap.ts"
import { NodeSDK } from '@opentelemetry/sdk-node';
import { PrometheusExporter } from '@opentelemetry/exporter-prometheus';

export const sdk = new NodeSDK({
    serviceName: 'orders-api',
    metricReaders: [new PrometheusExporter({ port: 9464 })]
});

sdk.start();
```

```yaml title="prometheus.yml"
scrape_configs:
    - job_name: orders-api
      static_configs:
          - targets: ['orders-api:9464']
```

Prometheus converts the names: `http.server.request.duration` becomes `http_server_request_duration_seconds`. For example, the 95th percentile of each route:

```promql
histogram_quantile(0.95, sum by (le, http_route) (rate(http_server_request_duration_seconds_bucket[5m])))
```

## OTLP

OTLP sends the traces and the metrics to an [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/), or directly to a backend that accepts it, such as Grafana Cloud, Jaeger, Datadog or Honeycomb:

```bash
npm install @opentelemetry/sdk-node @opentelemetry/sdk-metrics @opentelemetry/exporter-trace-otlp-http @opentelemetry/exporter-metrics-otlp-http
```

```ts title="instrumentation.bootstrap.ts"
import { NodeSDK } from '@opentelemetry/sdk-node';
import { PeriodicExportingMetricReader } from '@opentelemetry/sdk-metrics';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { OTLPMetricExporter } from '@opentelemetry/exporter-metrics-otlp-http';

export const sdk = new NodeSDK({
    serviceName: 'orders-api',
    traceExporter: new OTLPTraceExporter(),
    metricReaders: [new PeriodicExportingMetricReader({ exporter: new OTLPMetricExporter(), exportIntervalMillis: 10_000 })]
});

sdk.start();
```

The exporters send to `http://localhost:4318` by default. Configure the endpoint and the headers with the standard environment variables:

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=https://otlp.example.com
OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer <token>"
```

A Collector receives OTLP and exports the traces to Jaeger and the metrics to Prometheus:

```yaml title="otel-collector.yml"
receivers:
    otlp:
        protocols:
            http:
                endpoint: 0.0.0.0:4318
exporters:
    otlp/jaeger:
        endpoint: jaeger:4317
        tls:
            insecure: true
    prometheus:
        endpoint: 0.0.0.0:8889
service:
    pipelines:
        traces:
            receivers: [otlp]
            exporters: [otlp/jaeger]
        metrics:
            receivers: [otlp]
            exporters: [prometheus]
```

The [`observability` sample](https://github.com/axisparkjs-org/axispark/tree/main/samples/observability) has this setup in a `docker-compose.yml`, with Jaeger at `http://localhost:16686` and Prometheus at `http://localhost:9090`.

## Testing

The in-memory exporters of the SDK let the tests check the spans and the metrics of the application. Register the providers before the application is created:

```ts title="orders.e2e.spec.ts"
import { metrics, trace } from '@opentelemetry/api';
import { InMemorySpanExporter, SimpleSpanProcessor, TracerProvider } from '@opentelemetry/sdk-trace';
import { InMemoryMetricExporter, MeterProvider, PeriodicExportingMetricReader, AggregationTemporality } from '@opentelemetry/sdk-metrics';

const spans = new InMemorySpanExporter();
const reader = new PeriodicExportingMetricReader({ exporter: new InMemoryMetricExporter(AggregationTemporality.CUMULATIVE) });
trace.setGlobalTracerProvider(new TracerProvider({ spanProcessors: [new SimpleSpanProcessor({ exporter: spans })] }));
metrics.setGlobalMeterProvider(new MeterProvider({ readers: [reader] }));

// ...start the application and send requests...

expect(spans.getFinishedSpans().map((span) => span.name)).toContain('GET /api/orders/:id');
const { resourceMetrics } = await reader.collect();
```

To check the context propagation, also register a context manager (`AsyncLocalStorageContextManager` from `@opentelemetry/context-async-hooks`) and a propagator (`W3CTraceContextPropagator` from `@opentelemetry/core`), as the SDK does.
