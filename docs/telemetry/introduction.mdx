# Introduction

The `@axisparkjs/telemetry` package instruments the framework with [OpenTelemetry](https://opentelemetry.io/): a trace and metrics for every handler of the HTTP, WebSocket and MCP transports, the executions of the scheduled jobs, the rate limits, the stores and the health checks, and the trace of the request in the log entries.

The plugin only uses the OpenTelemetry **API**. The application chooses where the data goes (Prometheus, OTLP to Grafana, Datadog, Jaeger…) by configuring the OpenTelemetry **SDK** with the official packages, as OpenTelemetry recommends for libraries. When no SDK is registered, the API does nothing, and without the plugin the framework runs no instrumentation code at all.

## Install

```bash
npm install @axisparkjs/telemetry @opentelemetry/api @opentelemetry/sdk-node
```

Then install the exporter you need, for example `@opentelemetry/exporter-trace-otlp-http` and `@opentelemetry/exporter-metrics-otlp-http` for OTLP, or `@opentelemetry/exporter-prometheus`. See [Exporters](./exporters).

## 1. Start the SDK before the application

The SDK must be started before the application is created, so the tracer and the meter of the plugin export to it. Put it in its own file, named `*.bootstrap.ts` so the [scanner](../getting-started/first-steps#files-loaded-by-the-scanner) of the application does not load it, and import it first:

```ts title="instrumentation.bootstrap.ts"
import { NodeSDK } from '@opentelemetry/sdk-node';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { OTLPMetricExporter } from '@opentelemetry/exporter-metrics-otlp-http';
import { PeriodicExportingMetricReader } from '@opentelemetry/sdk-metrics';

export const sdk = new NodeSDK({
    serviceName: 'orders-api',
    traceExporter: new OTLPTraceExporter(),
    metricReaders: [new PeriodicExportingMetricReader({ exporter: new OTLPMetricExporter() })]
});

sdk.start();
```

```ts title="index.bootstrap.ts"
import { sdk } from './instrumentation.bootstrap';
import { app } from './app';

const bootstrap = async () => {
    try {
        await app.init();
        await app.run();
    } finally {
        await app.destroy();
        await sdk.shutdown(); // Exports the pending spans and metrics.
    }
};

bootstrap();
```

The resource of the SDK, such as `service.name`, `service.version` or `deployment.environment`, identifies the application in the backend. Set it in the SDK, with `serviceName` or the `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` environment variables.

## 2. Register the plugin

```ts title="app.ts"
import { AxiSparkFactory } from '@axisparkjs/core';
import { TelemetryPlugin, TelemetryPluginOptionsFactory } from '@axisparkjs/telemetry';

export const app = AxiSparkFactory.create({ name: 'Orders API', basePath: __dirname });

app.use(TelemetryPlugin, TelemetryPluginOptionsFactory.create());
```

The order of the plugins does not matter: the hooks are registered when the plugin is registered, before the application starts, so they observe every execution.

## Options

```ts
interface TelemetryPluginOptions extends PluginOptions {
    /** Whether to create spans. Defaults to true. */
    traces?: boolean;
    /** Whether to record metrics. Defaults to true. */
    metrics?: boolean;
    /** Whether to add the trace_id and span_id of the active span to the log entries. Defaults to true when the traces are enabled. */
    logCorrelation?: boolean;
    /** Whether to report the axispark.health.status gauge. Defaults to true when the metrics are enabled. */
    healthMetrics?: boolean;
    /** Handlers excluded from the instrumentation, such as the health checks. */
    ignore?: (context: ExecutionContext) => boolean;
}
```

For example, to leave the health endpoint of the HTTP plugin out of the traces:

```ts
TelemetryPluginOptionsFactory.create({
    ignore: (context) => context.target.name === 'HealthController'
});
```

## Trace context

- **HTTP:** the incoming `traceparent` and `tracestate` headers are extracted with the propagator of the SDK (W3C Trace Context by default), so the request continues the trace of the caller.
- **Handlers:** each handler runs inside the span of its request. The spans created by the handler, or by the OpenTelemetry instrumentations of the drivers it uses, become children of the request.
- **Scheduler:** each execution of a job starts a new root span, so the jobs never join the trace of the code that started the scheduler.
- **Logs:** the `trace_id` and `span_id` of the active span are added to the metadata of every log entry. See [Logging](../getting-started/logging#trace-context).

For example, an entry written by a handler with the `JsonFormatter`:

```json
{ "level": "INFO", "message": "Order 7 loaded", "metadata": { "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736", "span_id": "00f067aa0ba902b7" } }
```

## Errors and sampling

Following the semantic conventions, the expected HTTP errors (`4xx`) do not mark the span as an error. Only the `5xx` responses and the unhandled errors set the `ERROR` status and the `error.type` attribute. For the other transports, any error thrown by a step or the handler marks the span, even when a filter handles it.

The sampling is configured in the SDK. In production, use a ratio sampler that respects the decision of the caller, such as `new ParentBasedSampler({ root: new TraceIdRatioBasedSampler(0.1) })`, or the `OTEL_TRACES_SAMPLER=parentbased_traceidratio` and `OTEL_TRACES_SAMPLER_ARG=0.1` environment variables.

## Databases

The database queries are not instrumented by the framework. Use the OpenTelemetry instrumentations of the drivers, such as `@opentelemetry/instrumentation-pg`, `@opentelemetry/instrumentation-mysql2` or `@opentelemetry/instrumentation-mongodb`, in the `instrumentations` option of the SDK. Their spans are children of the request, because the handlers run inside its span.

The [`observability` sample](https://github.com/axisparkjs-org/axispark/tree/main/samples/observability) sends the traces and the metrics to an OpenTelemetry Collector, with Jaeger and Prometheus, in a `docker-compose.yml`.
