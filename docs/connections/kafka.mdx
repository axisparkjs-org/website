# Kafka

The Kafka plugin creates named Kafka clients and manages a producer and consumer for each connection. It is built on [`@confluentinc/kafka-javascript`](https://github.com/confluentinc/confluent-kafka-javascript), the client maintained by Confluent on top of [librdkafka](https://github.com/confluentinc/librdkafka), through its KafkaJS-compatible API. It passes each connection's configuration to the client and connects configured producers and consumers during plugin registration. See the [client documentation](https://github.com/confluentinc/confluent-kafka-javascript/blob/master/INTRODUCTION.md) for the full API, and the [KafkaJS documentation](https://kafka.js.org/docs/getting-started) for Kafka concepts.

## Install

Install the Kafka plugin in your project:

```sh
npm install @axisparkjs/kafka
```

`@confluentinc/kafka-javascript` is a native module. npm downloads a pre-built binary for Linux (glibc and musl, x64 and arm64), macOS (arm64) and Windows (x64) on the Node.js versions listed in its [requirements](https://github.com/confluentinc/confluent-kafka-javascript#requirements). On other platforms or Node.js versions, it is compiled from source during the installation, which needs Python, `make` and a C/C++ compiler.

## Configure connections

Register `KafkaPlugin` with options created by `KafkaPluginOptionsFactory`. Each connection needs a unique `name` and a `config`, including at least one broker:

```ts title="app.ts"
import { AxiSparkFactory } from '@axisparkjs/core';
import { KafkaPlugin, KafkaPluginOptionsFactory } from '@axisparkjs/kafka';

export const app = AxiSparkFactory.create({
    name: 'My application',
    basePath: __dirname
});

app.use(
    KafkaPlugin,
    KafkaPluginOptionsFactory.create({
        connections: [
            {
                name: 'ORDERS',
                config: {
                    clientId: 'orders-service',
                    brokers: ['localhost:9092']
                },
                producerConfig: {
                    idempotent: true
                },
                consumerConfig: {
                    groupId: 'orders-workers'
                }
            },
            {
                name: 'EVENTS',
                config: {
                    clientId: 'events-service',
                    brokers: ['broker-a:9092', 'broker-b:9092'],
                    ssl: true
                },
                autoInitialize: false
            }
        ]
    })
);
```

`config` uses the KafkaJS configuration format (`brokers`, `clientId`, `ssl`, `sasl`, `connectionTimeout`, `authenticationTimeout`, `requestTimeout`, `retry`, `logLevel` and `logger`) and is passed to the client in its `kafkaJS` block. `producerConfig` and `consumerConfig` are passed, also in their `kafkaJS` block, to `kafka.producer()` and `kafka.consumer()`, respectively. The plugin supplies a default consumer group ID of `<connection-name-lowercase>-group`; setting `consumerConfig.groupId` overrides it.

Some options are set when the client is created instead of on each call:

- `acks`, `compression` and `timeout` of the producer go in `producerConfig`, not in `send()`.
- `fromBeginning`, `autoCommit` and `autoCommitInterval` of the consumer go in `consumerConfig`, not in `subscribe()` or `run()`.

Use `librdkafkaConfig` to pass [librdkafka properties](https://github.com/confluentinc/librdkafka/blob/master/CONFIGURATION.md) that have no KafkaJS equivalent. They are passed next to the `kafkaJS` block, so do not repeat a property that `config` already sets:

```ts
{
    name: 'ORDERS',
    config: {
        clientId: 'orders-service',
        brokers: ['localhost:9092']
    },
    librdkafkaConfig: {
        'client.rack': 'eu-west-1a'
    }
}
```

By default, the plugin creates and connects both a producer and consumer for every connection during registration. Set `autoInitialize: false` to create them lazily when first injected. To initialize only one client automatically, configure the flags separately:

```ts
{
    name: 'PUBLISH_ONLY',
    config: {
        clientId: 'publisher',
        brokers: ['localhost:9092']
    },
    autoInitialize: {
        autoInitializeProducers: true,
        autoInitializeConsumers: false
    }
}
```

Connection names must be unique. The manager connects initialized clients during plugin registration and disconnects them when the plugin stops. Initialization errors are logged; the failed producer or consumer is not registered. A connection to an unreachable broker fails after the connection setup timeout (`connectionTimeout` + `authenticationTimeout`), once per attempt of `retry.retries`, so it delays the start of the application.

## Inject a producer or consumer

Use `@InjectKafkaProducer(name)` or `@InjectKafkaConsumer(name)` to inject the producer or the consumer of a named connection. The `Kafka`, `Producer`, `Consumer` and `Admin` types are exported by `@axisparkjs/kafka`:

```ts
import { Injectable } from '@axisparkjs/di';
import { InjectKafkaProducer, Producer } from '@axisparkjs/kafka';

@Injectable()
export class OrderPublisher {
    constructor(
        @InjectKafkaProducer('ORDERS')
        private readonly producer: Producer
    ) {}

    async publish(order: { id: string; status: string }): Promise<void> {
        await this.producer.send({
            topic: 'orders',
            messages: [{ key: order.id, value: JSON.stringify(order) }]
        });
    }
}
```

A consumer is connected by the plugin but still needs a subscription and a `run` handler:

```ts
import { Injectable } from '@axisparkjs/di';
import { InjectKafkaConsumer, Consumer } from '@axisparkjs/kafka';

@Injectable()
export class OrderListener {
    constructor(
        @InjectKafkaConsumer('ORDERS')
        private readonly consumer: Consumer
    ) {}

    async start(): Promise<void> {
        await this.consumer.subscribe({ topic: 'orders' });
        await this.consumer.run({
            eachMessage: async ({ message }) => {
                console.log(message.value?.toString());
            }
        });
    }
}
```

With `autoInitialize: false`, the plugin creates and connects the requested client when its injection token is first resolved. The connection manager tracks it and disconnects it on shutdown.

## Inject a Kafka client

Use `@InjectKafkaConnection(name)` when you need the underlying `Kafka` client—for example, to create an additional producer that you manage yourself:

```ts
import { InjectKafkaConnection, Kafka } from '@axisparkjs/kafka';

export class AdminService {
    constructor(
        @InjectKafkaConnection('ORDERS')
        private readonly kafka: Kafka
    ) {}

    createProducer() {
        return this.kafka.producer({ kafkaJS: { acks: 1 } });
    }
}
```

The plugin only manages the producer and consumer it creates for each connection. If you create additional producers, consumers or admin clients yourself, connect and disconnect them in your service. The corresponding injection tokens are `KAFKA_CONNECTION_<name>`, `KAFKA_PRODUCER_<name>`, and `KAFKA_CONSUMER_<name>`, returned by `kafkaConnectionToken(name)`, `kafkaProducerToken(name)` and `kafkaConsumerToken(name)`, which always return the same token instance for the same name. The decorators are the recommended way to resolve them.

## Use the connection manager

Inject `KafkaConnectionManager` to look up a named client, producer, or consumer, or to retrieve copies of the managed maps:

```ts
import { KafkaConnectionManager } from '@axisparkjs/kafka';

export class ConnectionInspector {
    constructor(private readonly connections: KafkaConnectionManager) {}

    inspect(): void {
        const kafka = this.connections.getConnection('ORDERS');
        const producer = this.connections.getProducer('ORDERS');
        const consumer = this.connections.getConsumer('ORDERS');

        console.log(kafka, producer, consumer);
        console.log([...this.connections.getAllConnections().keys()]);
    }
}
```

The `getConnection`, `getProducer`, and `getConsumer` methods return `undefined` when the name is unknown or the client has not been initialized. Each `getAll...` method returns a new map, so changing that map does not change the manager's internal state.

## Health checks

The plugin registers a [health check](../getting-started/health-checks#built-in-checks) named `kafka:<name>` for each configured connection. It connects an admin client, without retries, and requests the cluster ID, which is reported in its details. If the check fails, the application is reported as `Unhealthy`. Set `healthChecks: false` in the plugin options to disable these checks.

## Migrating from KafkaJS

Before this version, the plugin was built on [`kafkajs`](https://github.com/tulios/kafkajs), which is no longer maintained. The plugin options, the decorators and `KafkaConnectionManager` are the same, so an application that only configures the plugin needs no changes. Code that uses the injected clients may need these changes:

| Before | Now |
| --- | --- |
| `import type { Producer } from 'kafkajs'` | `import { Producer } from '@axisparkjs/kafka'` (also `Kafka`, `Consumer`, `Admin`, `KafkaConfig`, `ProducerConfig` and `ConsumerConfig`). |
| `producer.send({ topic, acks, compression, timeout, messages })` | `acks`, `compression` and `timeout` in `producerConfig`. |
| `consumer.subscribe({ topic, fromBeginning: true })` | `fromBeginning: true` in `consumerConfig`. |
| `consumer.run({ autoCommit, autoCommitInterval, eachMessage })` | `autoCommit` and `autoCommitInterval` in `consumerConfig`. |
| `kafka.producer(config)` on an injected client | `kafka.producer({ kafkaJS: config })`, and the same for `consumer()` and `admin()`. |
| Errors checked by `error.name` or `error.type` | Check `error.code`. |
| `eachBatch` with several messages per batch | Each batch contains one message. |
| `admin.describeCluster()` in the health check details (`brokers`, `controller`) | `admin.clusterId()`: the details contain the `clusterId`. |

The client reports the options that it does not support with an error that explains the change. See the [migration guide](https://github.com/confluentinc/confluent-kafka-javascript/blob/master/MIGRATION.md) of `@confluentinc/kafka-javascript` for the complete list of differences.
