# Installation

Thanks to AxiSpark.js, you can easily install the OpenApi Plugin in your project. Follow the steps below to get started.

## Prerequisites

Before using the OpenApi Plugin, you need to have the HTTP Plugin installed and configured in your project. The OpenApi Plugin relies on the HTTP Plugin to extract information about your API endpoints and to expose the OpenAPI documentation as REST endpoints. Please, check the [HTTP Plugin documentation](../http-plugin/installation.mdx)

## 1. Install the OpenApi Plugin

You can use npm or any other package manager to install the OpenApi Plugin. Run the following command in your project directory:

```
npm install @axispark/openapi
```

## 2. Import the OpenApi Plugin

Once the installation is complete, you can import the OpenApi Plugin into your project. Add the following line to your code:

```ts
import { AxiSparkFactory } from '@axisparkjs/core';
import { OpenApiPlugin, OpenApiPluginOptionsFactory } from '@axisparkjs/openapi';

export const app = AxiSparkFactory.create({
    ...
});

app.use(OpenApiPlugin, OpenApiPluginOptionsFactory.create({
    // Configuration options
}));
```

## 3. Configure the OpenApi Plugin

OpenApi Plugin offers a `OpenApiPluginOptionsFactory` class that allows you to configure the plugin with various options. The `OpenApiPluginOptionsFactory.create()` method accepts an object with the following properties:


```ts name="openapi-plugin-options.ts"
/**
 * Interface representing the options for configuring the OpenAPI plugin.
 */
export interface OpenApiPluginOptions extends PluginOptions {
    /**
     * Information about the API.
     */
    info: {
        title: string;
        version: string;
        description?: string;
        termsOfService?: string;
        contact?: {
            name?: string;
            url?: string;
            email?: string;
        };
        license?: {
            name: string;
            url?: string;
            identifier?: string;
        };
        summary?: string;
        externalDocs?: {
            description?: string;
            url: string;
        };
        tags?: {
            name: string;
            description?: string;
        }[];
        servers?: {
            url: string;
            description?: string;
        }[];
    };
    /**
     * If true, the OpenAPI plugin will use the global prefix for the documentation routes. If false, it will not use the global prefix.
     */
    globalPrefix?: boolean;
    /**
     * Url path for the OpenAPI documentation.
     */
    docsUrl?: string;
    /**
     * Url path for the OpenAPI JSON document.
     */
    jsonDocumentUrl?: string;
    /**
     * Url path for the OpenAPI YAML document.
     */
    yamlDocumentUrl?: string;
    /**
     * If true, the OpenAPI plugin will expose the JSON document as a REST endpoint.
     */
    exposeJson?: boolean;
    /**
     * If true, the OpenAPI plugin will expose the YAML document as a REST endpoint.
     */
    exposeYaml?: boolean;
    /**
     * If true, the JSON responses documented with @OpenApiResponse() are serialized with their schema by the adapters that support it (Fastify).
     */
    serializeResponses?: boolean;
}
```

## Serializing the responses with their schemas

With the Fastify adapter, set `serializeResponses: true` to serialize the JSON responses of the documented routes with the schemas of the document, using the `fast-json-stringify` serializer of Fastify instead of `JSON.stringify`:

```ts title="app.ts"
app.use(OpenApiPlugin, OpenApiPluginOptionsFactory.create({ info: { title: 'Shop', version: '1.0.0' }, serializeResponses: true }));
```

- The schema of each status code of `@OpenApiResponse()` is used for that status, and the `default` response for the rest.
- Only the bodies that match the root of the schema are serialized with it: an object for a schema of a class, an array for an `array` schema. `null`, primitives and the other bodies are serialized with `JSON.stringify`.
- Routes that serve several handlers (versions or hosts of the same path) are always serialized with `JSON.stringify`.
- The Express adapter ignores the option.

:::warning
The properties that are not in the schema are **not sent**. Enable the option only when the `@OpenApiProperty()` of your response classes describe every property that the clients need.
:::
